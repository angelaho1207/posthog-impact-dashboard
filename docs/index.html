Who are PostHog's most impactful engineers?

Impact = quality-weighted work shipped in critical parts of the system + how much an engineer makes others' work better and faster. Score is a weighted blend of four percentile ranks (0 = lowest engineer, 100 = highest), so every number below is "better than X% of ranked engineers". Hover any column header for its definition. How to read a component

  • Delivery: each merged PR = tier of the most critical file touched (T1 ×3 … T4 ×0.5) × title type (fix/perf ×1.3, feat ×1.2, refactor ×0.8, chore ×0.5, docs ×0.3) × difficulty keywords (×0.6–1.5) × log(real lines, generated files excluded, capped at p95). Summed over 90 days. Why: rewards hard work in risky code, not volume.
  • Review substance: human, non-stamp reviews only (stamp = no inline comments and <80 chars). Points = (1 + 0.5/inline comment + long body + changes requested + review keywords) × reviewed PR's tier × 1.5 if it landed before the PR's last commit. Why: measures reviews that changed the code, not rubber stamps.
  • Unblocking: per PR, the reviewer's first substantive review: ≤4h ×1.5, ≤24h ×1.2, ≤72h ×1.0, slower ×0.7, scaled up to +30% by the helped engineer's delivery percentile. Plus substantive comments on others' PRs. Why: fast, useful feedback keeps the team moving.
  • Ownership & reach: max(depth, breadth) percentile. Depth = share of an area's substantive PRs (areas with ≥10). Breadth = number of areas with ≥3 substantive PRs. +5 per area where the engineer is top author and reviews others' PRs there. Why: rewards owning a system or meaningfully spanning several, not scattered small edits.
